# Audit: eximtours (high)

## Shrnutí

The adapter scrapes eximtours.cz's /last-minute page for a GroupSearch2 `locations[]` seed list, then re-targets each seed's querystring at /searchresult/getsearch and parses the server-rendered `#divHotelCard` HTML out of the JSON envelope. Field mapping is genuinely good: I verified two offers end-to-end against their own detail pages and every mapped field (price per person, total, departure date, nights, board, stars, country, locality) matched exactly, and the module's "originalPrice/discount are total-based" premise held on both (44 760 − 12 780 = 31 980; 91 040 − 4 000 = 87 040). The price band is also healthy — the live run returned 12 790 to 84 910 CZK/person including real exotic packages (Mexiko 84 910, Mauricius 72 060, Maledivy 43 520), so the "only cheap domestic stays" failure mode does not apply. The problem is volume and breadth: the run returned 197 offers where the site's own paging counters report thousands. The adapter reads only page 1 (20 cards) of each destination and never pages, and its hardcoded 12-destination list covers only 10 of the 20 destinations the site actually offers in last minute — omitting Španělsko, which alone has 1 487 products and is the first entry in the site's own "TOP 5 last minute destinace" nav. Two smaller field defects: room-only offers labelled "bez stravy" fall through the board regex to 'unknown' (13/197), and every Kapverdy offer gets country: null, which silently excludes it from the exotika profile that explicitly asks for Kapverdy.

## Nálezy k opravě

### 1.

COVERAGE — only page 1 of N is ever read. /searchresult/getsearch returns `paging: {Count, PageSize: 20, RowsToSkip: 0}` and fetchOffers issues exactly one request per destination, so it always takes the first 20 cards. Live counts measured today: Řecko Count=1357 → 20 taken (1.5%); Egypt 316 → 20 (6.3%); Maledivy 143 → 20 (14%); Thajsko 120 → 20 (17%); only Kapverdy (Count=17) is fully covered. Whole live run = 197 offers. Paging is trivially available: the site's own bundle /Scripts/web/index.CJApklS_.js builds `pSTG=<skip>&pITG=<take>` for this exact endpoint, and I confirmed it works — https://www.eximtours.cz/searchresult/getsearch?<Řecko seed query>&pSTG=20&pITG=20 returns a disjoint set of 20 (page 1 starts with 'Coral', page 2 with 'Zotos Studios & Apartments').

### 2.

COVERAGE — the first page is not the cheap end, so the bargain tail is systematically lost. This matters because the whole board is a discount board. The site's own seed metadata says Řecko starts from 11 409 Kč and Egypt from 11 490 Kč per adult, but the adapter's cheapest Řecko offer was 13 690 and cheapest Egypt 12 790. Page 2 of Řecko (pSTG=20) is entirely cheaper stock — min 13 190, max 16 190, every one of its 20 hotels absent from page 1.

### 3.

COVERAGE — the hardcoded TARGET_DESTINATIONS list (src/sources/eximtours.ts:15-28) covers only 10 of the 20 destinations live in the site's own last-minute widget. Never queried at all: Katar (from 25 307), Malajsie (25 748), Omán (17 645), Srí Lanka (22 425, Count=71), Velká Británie (17 957), Španělsko (10 431, Count=1487), Francie (21 565), Maroko (13 239), Seychely (45 746, Count=21), Keňa (30 505). Španělsko is the single largest last-minute destination on the site and is listed first in eximtours.cz's own 'TOP 5 last minute destinace' nav (Španělsko, Řecko, Kapverdy, Egypt, Tunisko).

### 4.

COVERAGE — 2 of the 12 hardcoded targets do not exist in the live seed list and are skipped on every single scan: 'Turecko' and 'Kuba' (adapter logs 'no seed found for X, skipping'). Meanwhile 'Tunisko', which the site itself promotes in its TOP-5 last-minute nav, is not in TARGET_DESTINATIONS nor in the GroupSearch2 widget, so it is unreachable via the current seeding strategy. Net effect: 10 real destination queries per scan, 2 wasted list entries.

### 5.

FIELD — board regex misses the label 'bez stravy'. src/sources/eximtours.ts:216 matches /All inclusive|Polopenze|Plná penze|Snídaně|Bez stravování/i, but the DS=2 (dynamic-packaging / Hotelbeds) cards spell room-only as 'bez stravy', which the regex does not extract, so normalizeBoard(null) returns 'unknown'. Measured live: 7 of 20 Thajsko cards (35%), 2 of 20 Srí Lanka, 13 of 197 across the whole run. normalizeBoard already handles the string (`s.includes('bez strav')` at src/core/normalize.ts:13) — only the extraction regex is too narrow. Consequence beyond a wrong label: board 'unknown' makes computeMatchKey return null (src/core/normalize.ts:154), so these offers are dropped from cross-source matching entirely. Example: https://www.eximtours.cz/hotely/thajsko/phuket-a-okoli/phuket/phuket-sea-resort-sha-by-zuzu (card says 'bez stravy', adapter emits board='unknown').

### 6.

FIELD — every Kapverdy offer gets country: null. The site's country label on the card is 'Kapverdské ostrovy', but COUNTRY_BY_KEY (src/core/normalize.ts:27) only knows 'Kapverdy', so isKnownCountry() is false and parseCard stores null. Measured: 17 of 17 Kapverdy offers live. This is not cosmetic — matchesCountry (src/core/filters.ts:9) returns false for a null country, so these offers can never match the `exotika` profile, which explicitly lists `Kapverdy` in config/watch.yaml. They also get a null matchKey and null hotelKey, so they are excluded from cross-source merging and from the hotel reference rung of discount v2. One-line fix: COUNTRY_BY_KEY.set('kapverdske ostrovy', 'Kapverdy'). Example offer: https://www.eximtours.cz/kapverdske-ostrovy/sal/santa-maria-sal/hotel-oasis-atlantico-belorizonte (26 090 Kč/os, AI, 4*, 2026-08-18, 7 nocí) — country stored as null.

### 7.

FIELD (low) — departureAirport is hardcoded null (src/sources/eximtours.ts:228) even though every card carries the route explicitly: 'Brno - Kavala', 'Praha - Male', 'Praha - Abu Dhabi', plus full leg times. It genuinely varies — the Coral offer I verified departs from Brno, not Prague. tourOperator is likewise null while the card states 'Pořádající CK: DER Touristik CZ a.s. (majitel obchodní značky EXIM tours)'. Ranked low because 11 of 13 adapters in src/sources/ hardcode departureAirport: null (only cesys.ts and zajezdy.ts populate it), so this is a project-wide convention rather than an eximtours regression; a null airport buckets under '*' in computeMatchKey, which causes missed merges rather than wrong ones.

### 8.

FIELD (informational, no action) — sourceOfferKey = offerKeyHash([title, departureDate, nights, board]) omits country/locality, and the `seen` dedupe set in fetchOffers is global across all destinations. Two same-named hotels in different countries sharing a date/nights/board would silently collide and the second would be dropped. No loss observed in this run (9 destinations × 20 cards + 17 Kapverdy = exactly 197 offers, zero collisions), but the collision surface grows if paging is added.

Severity medium, not high: nothing emitted is incorrect (field-level parsing checks out), and full coverage was never reachable — pITG>20 is not honoured (&pITG=60 returns an HTML page with 0 divHotelCard, with and without X-Requested-With), so each extra 20 rows costs one request, and covering the live seed set fully would be ~100+ requests against the spec's ~50-150/run budget for all 16 sources.
