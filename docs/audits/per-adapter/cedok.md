# Audit: cedok (critical)

## Shrnutí

src/sources/cedok.ts fetches exactly four URLs: https://www.cedok.cz/last-minute/?page=1..4&order=priceAsc, and parses the SSR offer cards (dedupe of the mobile/desktop double-render works correctly, 50 nodes -> 25 unique per page). The field mapping is sound and the price is genuinely per-person, all-in, for the stated nights — the production red flag is NOT a wrong price field, it is the `order=priceAsc` parameter. Sorting cheapest-first and stopping after 4 pages pins the adapter to the 100 CHEAPEST offers out of the 3 295 the site's own offers-counter reports for that section (3.0% coverage), which is why the board shows nothing above 2 719 CZK and nothing but 1-2 night domestic stays. Cedok's actual last-minute inventory — the all-inclusive seaside/exotic flight packages at 11 000-51 000 CZK/person, which is where 76-92% of the offers carry a 19-58% discount — is 100% absent. For a discount board this is the worst possible 3% to fetch: 0 of 25 offers on the adapter's first page have any claimedDiscountPct at all, versus 23 of 25 on the default-sorted flight pages. Two secondary field bugs (transport selector, missing departureAirport) only bite on flight offers, so they are currently invisible but would surface the moment coverage is fixed. Effectively, Cedok as a seaside/exotic seller is missing from the board entirely.

## Nálezy k opravě

### 1.

COVERAGE, CRITICAL — `order=priceAsc` + LAST_MINUTE_PAGES=4 restricts the adapter to the 100 cheapest offers of 3 295. src/sources/cedok.ts:123 builds `${BASE_URL}/last-minute/?page=${page}&order=priceAsc` for page 1..4. The site's own `[data-testid="offers-counter"]` on that exact URL reads "(3 295 nabídek)" = 132 pages of 25. Live adapter run: 100 offers, price min/median/max = 880 / 2 240 / 2 719 CZK, transport `own` for 100/100, nights 1 or 2 for 99/100, countries Česká republika 47, Slovensko 17, Polsko 15, Bosna a Hercegovina 5, Itálie 5, Německo 3, Maďarsko 2, Francie 2, Srbsko/Rakousko/Chorvatsko/Slovinsko 1 each. Zero Egypt, Turecko, Řecko, Kanáry, Emiráty, Thajsko, Maledivy.

### 2.

COVERAGE, CRITICAL — what the adapter never sees. Fetching the SAME URL without the `order` param (https://www.cedok.cz/last-minute/) and parsing it with the adapter's own `parseCedokListing` yields 25 offers priced 11 004-28 090 CZK/person: Albánie 6, Egypt 4, Tunisko 3, Portugalsko 3, Řecko 3, Kanárské ostrovy 2, Bulharsko 2, Turecko 2 — all 7-night All-inclusive flight packages. Deeper default pages go higher still: page 6 tops at 36 290 CZK, page 8 at 50 990 CZK (Maledivy, Thajsko, Keňa, Gruzie, Švýcarsko). Example the board is missing: https://www.cedok.cz/dovolena/tunisko/djerba/hotel-zita-beach-resort,DJE2ZIT/ — Djerba, 4*, 7 nocí All inclusive, 05.08-12.08.2026, 27 890 -> 13 090 CZK/os (-53%).

### 3.

COVERAGE, CRITICAL — the adapter scrapes the one price band that has no discounts. Running `parseCedokListing` over saved pages and counting offers with a non-null claimedDiscountPct: priceAsc page 1 = 0/25 discounted; priceAsc page 6 = 1/25 (10%); priceAsc page 12 = 2/25 (10%, 5%). Default-ordered (flight) page 1 = 19/25 with 6-58% off; default page 4 = 23/25 with 19-58% off. The discount-detection logic in cedok.ts:58-63 is correct but is being pointed at inventory that carries no `[data-testid="base-price"]`, so claimedOriginalPrice/claimedDiscountPct are effectively dead for this source in production.

### 4.

COVERAGE, note on the fix — `order=priceDesc` is silently ignored by the site. https://www.cedok.cz/last-minute/?page=1&order=priceDesc returns the identical offer set to the no-order default (827 181 vs 827 110 bytes, same 25 hotels in the same order), and "desc" pages 4/6/8 are not monotonically decreasing (9 759-24 990, 3 990-36 290, 11 190-50 990). So flipping the sort direction will NOT work; the fix is to drop the `order` param entirely (the site's default ordering already surfaces the discounted flight packages first) and/or page much deeper than 4.

### 5.

FIELD, transport is `unknown` for 100% of flight offers — selector mismatch. src/sources/cedok.ts:82 does `card.find('.icon-car-2, .icon-plane, [class*="icon-plane"]')`, but the flight card's icon class is `icon-airplane`, and the string "icon-airplane" does not contain the substring "icon-plane", so `[class*="icon-plane"]` never matches. The selector returns empty, the code falls back to the whole `cardText`, and `normalizeTransport` only matches `letec`/`flight` — the card text says "Praha (letiště) 04:50", and `letiste` contains neither. Measured on live pages: lm_desc4 20/25 unknown, lm_desc1 20/25, lm_desc6 22/25, lm_desc8 20/24 — every single `icon-airplane` card resolved to `unknown`. Own-transport cards (`icon-car-2` -> "Vlastní doprava") work correctly. Verified on https://www.cedok.cz/dovolena/tunisko/djerba/hotel-zita-beach-resort,DJE2ZIT/ (adapter transport=unknown, site = flight from Ostrava).

### 6.

FIELD, departureAirport is hardcoded null although the card carries it. src/sources/cedok.ts:103 sets `departureAirport: null`, but the very node the transport selector should be reading contains the airport: `[class*="icon-airplane"]`.parent() text is "Praha (letiště) 04:50", "Ostrava (letiště) 04:25", "Ostrava (letiště) 08:00". Every flight offer loses its departure airport, so PRG/OSR filtering on the board can never work for cedok. Currently masked because no flight offers are fetched at all.
